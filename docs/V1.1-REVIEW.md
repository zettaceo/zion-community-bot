# ZION v1.1 — Review and Deployment Gates

Status: **development only**  
Branch: `zion-v1.1-dev`  
Stable base: `zion-v1`

ZION v1.1 must not be deployed merely because CI is green. Runtime validation on the host and Telegram is a separate gate.

## Scope completed in the development branch

### Community OS

- bilingual PT-BR/EN start, help, rules and onboarding;
- explicit privacy disclosure for AI, knowledge gaps and AMA retention;
- recurring announcement scheduler;
- AMA open / collect / list / close workflow;
- bounded retention of closed-AMA question text;
- existing reports, polls, one-shot scheduling and 24h brief preserved.

### Intelligence preparation

- section-level source labels for grounded answers;
- explicit trust-boundary tags around official context and untrusted user questions;
- prompt-injection instructions hardened;
- knowledge gaps remain local, sanitized and retention-bounded;
- provider-independent tests exercise the Mistral prompt boundary without real API credentials.

### Guardian

- Unicode/IDNA hostname normalization before domain policy comparison;
- hidden Telegram URL entities remain covered;
- visually similar Unicode domains do not inherit an ASCII allowlist entry;
- distributed chat-burst detection across multiple users;
- distributed burst only enters temporary ELEVATED mode; it does not create a user strike, mute or ban by itself;
- existing raid, per-user flood, containment, wallet-secret and lockdown behavior preserved.

### Operations

- SQLite `PRAGMA quick_check`;
- aggregate DB/WAL/SHM size;
- low-disk warning threshold;
- recent Telegram update-lag sample;
- successful Mistral latency avg/p95 over 24h;
- `/diagnostics` operator command;
- deduplicated operational alerts;
- localhost dashboard includes SQLite integrity and DB size.

### Remote operations preparation

- Tailscale + SSH public-key runbook;
- no router port forwarding;
- no private keys or auth tokens in Git;
- read-only remote-access preflight script;
- deployment model intentionally rejects a privileged self-hosted GitHub runner for now.

## CI gate

Required before review:

```bash
bash scripts/validate.sh
```

This covers compile, imports, unit tests, shell syntax, tracked sensitive-file checks and repository secret scanning.

## Host validation gate

When the operator has secure SSH access to the ZION host:

1. confirm production service is healthy and record current commit;
2. create a local pre-deploy backup;
3. fetch the reviewed v1.1 commit without changing runtime secrets;
4. run `bash scripts/validate.sh` before stopping production;
5. verify database migration against a copy of production data;
6. verify `.env` compatibility for all new settings using defaults;
7. perform a controlled short cutover only after the previous gates pass.

## Telegram live gate

After a future approved cutover, validate in this order:

1. `/status`
2. `/health`
3. `/diagnostics`
4. `/aistatus`
5. public `/help`, `/rules`, `/privacy`
6. AMA open/question/list/close in a test chat
7. one recurring schedule with a short controlled interval, then cancel it
8. unauthorized ASCII and Unicode-lookalike link behavior using a disposable test account
9. flood and distributed-burst behavior in a dedicated test chat, not the production community

## AI gate

Mistral remains independent from the v1.1 code deployment.

Do not enable AI until:
- a newly generated key is stored locally, never in Git or chat;
- `ZION_AI_ENABLED=true` is an explicit operator decision;
- support-only `/ask` is tested first with `ZION_AI_OBSERVE=false`;
- token budget and circuit breaker are confirmed;
- observe-only moderation is enabled only after support behavior is stable.

AI never gains direct punitive authority in this release.

## Rollback gate

Before deployment, record:
- previous commit SHA;
- backup directory;
- service unit checksum or known-good repository version;
- SQLite backup path.

If any live gate fails, restore the previous code and local state according to the operations runbook before further debugging.
