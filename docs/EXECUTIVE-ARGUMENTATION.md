# Executive conversation policy

The response planner chooses a bounded mode from the current question, trusted
agent identity and presence of approved evidence. It emits reviewed instructions,
not user-supplied system text. Generated reasoning traces and argument trees are
not persisted or exposed. Conversation state remains untrusted context; it cannot
supply official facts, permission or credentials.

For a substantive objection, the response should acknowledge its valid part,
explain relevant documented differences, identify missing comparison data and
state limitations. It must address the current concern instead of dumping a
feature catalogue, asserting superiority or pressuring a purchase. A claim about
cheaper established competitors is not answered as an ordinary FAQ. FREYR must
answer a commercial objection before continuing partnership qualification.
EIR prioritizes diagnosis over debate when someone is reporting a problem.

| Identity | Response responsibilities | Boundaries |
| --- | --- | --- |
| ZION | Product value, community, institutional concerns, public roadmap; factual and non-defensive | No invented superiority; distinguish current availability from plans |
| MIMIR | Mechanisms, networks, routes, providers and trade-offs | No universal execution claims; separate simulation/documentation from proven execution; no inferred private implementation |
| EIR | Acknowledge the problem, separate report from fact, request the next safe detail, indicate human review | No secret requests, false account access, recovery or resolution claims |
| FREYR | Explain documented value, address pricing objections, qualify business objectives | No invented ROI, payment, commission, equity, exclusivity, contract or deadline |

The roles do not grant operational authority. Guardian remains deterministic;
no planner, model or provider may punish a member, change permissions, execute a
trade or approve a business agreement. Security instructions, public-interface
boundaries and output validation remain shared across the four identities.

## Evidence and acceptance

`evaluations/cognitive-v2.jsonl` retains the original 100 cases and appends eight
synthetic objection, business, support and technical cases. Case v2-101 preserves
the exact competitive objection from the mission. Cases v2-103 through v2-108
exercise continuation under the intended role. The generation evaluator uses the
gold identity; it does not certify Telegram routing or autonomous handoff.

`--case-ids` selects up to ten existing cases, validates IDs before provider
access, and cannot be combined with `--full`. All live calls retain the same
monetary admission and stop-on-failure behavior. No arbitrary prompt can be
injected through the case selection interface.

A planner regression proves mode selection, not persuasive or factual quality.
Every generated answer remains REVIEW_REQUIRED until inspected against public
source evidence. A safe generic answer is not proof of a strong response, and a
successful generation test is not real Telegram acceptance.
